# Deployment Documentation

Phase 6B operates a manually approved Azure demo in Central US. Read [CI/CD overview](architecture/cicd-overview.md), [Azure demo continuous delivery](architecture/future-azure-deployment.md), [Azure setup and release](guides/future-azure-setup.md), [observability and support references](guides/observability-support.md), [launch hardening and content promotion](guides/launch-hardening-performance.md), [store and Square foundation](guides/store-square-foundation.md), and [public storefront and configurator](guides/store-public-configurator.md).

The demo enables cookie-free public browser performance telemetry, uses CSP report-only mode, disables anonymous Parent registration, and provisions an Azure-managed Communication Services email sender for Admin MFA and password recovery. `Microsoft.Communication` must be registered once at subscription scope. The workflow reuses an existing registration and attempts registration only when it is missing, so the normal resource-group-scoped deployment identity does not need subscription-level registration permission after bootstrap. Production must enforce CSP only after violation review and must verify the club sender domain before launch. Apply the launch-hardening migration before running the idempotent media derivative backfill. Selective content promotion remains dry-run-only until a separate production environment and a disposable rehearsal are approved.

The demo budget update is idempotent: an existing budget retains its original Azure-managed time period while amount and notification thresholds are reconciled. New deployments create the period only when the budget does not yet exist.

Commerce deployments must keep `Store__Enabled=false` until the documented final cutover. The demo deployment sets `Store__PublicPreviewEnabled=true`, which exposes the catalog, configurator, and non-personal cart to internal reviewers while Square checkout, webhooks, order creation, reservations, and commerce workers remain disabled. Production should keep the preview flag false unless an equally explicit review decision is recorded. Square access tokens and webhook signature keys belong in Azure Key Vault and enter App Service only through Key Vault references. The private one-time catalog import can run while full commerce is disabled, but only after the Square access-token secret URI and selected location ID are supplied through the existing deployment inputs.
